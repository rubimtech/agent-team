# Runtime-верификация: доказать, что в Revit твой код

Рецепт для задач вида «проверь новые MCP-тулы вживую», где сборка уже зелёная, но
запущенный Revit мог поднять чужую сборку.

## Почему «сборка успешна» ничего не доказывает

Цепочка деплоя теряет информацию о провале на трёх уровнях:

1. Копирование — с `-ErrorAction SilentlyContinue`: заблокированные файлы пропускаются
   без ошибки и без предупреждения.
2. Проверка полноты — `Test-Path` по списку обязательных сборок: проверяет **существование**,
   а не свежесть, поэтому устаревшая DLL её проходит.
3. Версии манифестов патчатся на текущий билд независимо от того, какая DLL легла на диск —
   это дополнительно маскирует расхождение.

Итог: MSBuild рапортует «Сборка успешно завершена. Ошибок: 0», а в Revit — старая сборка.

## Порядок проверки (до первого содержательного вызова)

```bash
# 1. Хэши: своя сборка vs задеплоенная
md5sum revitCopilot/bin/Release.RNN/revitCopilot.dll
md5sum "$LOCALAPPDATA/RuBIMtech/ReVibe/plugins/revitCopilot/RNN/revitCopilot.dll"

# 2. Grep по строке-маркеру своего среза — решающий признак
grep -c "<marker>" "$LOCALAPPDATA/.../RNN/revitCopilot.dll"     # 0 у чужой сборки
grep -c "<marker>" revitCopilot/bin/Release.RNN/revitCopilot.dll  # есть у своей

# 3. Признак блокировки (отличается от «собрали не то дерево»)
python -c "open(r'...\RNN\revitCopilot.dll','r+b')"   # PermissionError => держит Revit
```

## Развилка диагноза

| Симптом | Диагноз |
|---|---|
| Хэши разные, маркер есть только в своей DLL, файл открывается на запись | Собрано/задеплоено **не то дерево** (чужой worktree занял общий каталог деплоя) |
| Хэши разные, маркера нет ни там, ни там, файл **не** открывается на запись | DLL залочена работающим Revit — нужен рестарт Revit, затем пересборка |
| `tools/list` содержит старую версию тула, хотя в коде он есть | Тот же корень: проверить маркер, не чинить сервис |

Комментарий в `git log`, которого нет на диске, — указание на неверный worktree.
Один deploy-каталог на все worktree: `git worktree list` покажет, кто ещё собирает
в тот же `%LOCALAPPDATA%`.

## Проверка «это вообще другой билд» по ответу тула

Не только по хэшу: если поле, которое эмитит текущий исходник, отсутствует в ответе,
это не регрессия сервиса. Сравни ожидаемый набор ключей ответа с фактическим —
расхождение по **составу ключей** доказывает чужой бинарник быстрее, чем значения.

## Что делать, пока ждёшь рестарт Revit

Проверяй то, что не зависит от новых сборок, на текущей: транспорт, конверт ответа,
`get_status`, инвентарь документа, регресс нетронутых инструментов. Каждый такой пункт
помечай как проверенный на **старой** сборке — иначе его результат молча смешается с
результатами на новой.
