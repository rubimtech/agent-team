# Добавить роль агента в репозиторий на Kilo

Роль — это markdown-файл роли плюс две записи о ней. Файл без регистрации не существует для пользователя:
агента не будет в списке выбора.

## Три места, которые надо тронуть

| Место | Что добавляется | Зачем |
|---|---|---|
| `.kilo/agent/<name>.md` | роль: front-matter + тело | сам промпт роли |
| `.kilo/kilo.json` → `agent.<name>` | `mode`, `description`, `prompt`, `permission` | без записи агент не появится в списке; остальные агенты репозитория тут перечислены явно |
| `AGENTS.md` → таблица «Роли агентов» | строка `Роль / Файл / Когда использовать / Модель / Инструменты` | каталог ролей проекта; без строки агент невидим тому, кто читает AGENTS.md |

Front-matter роли: `description` (одна строка «<имя> — <что делает>»), `mode: primary` (выбирается
пользователем) или `subagent` (только делегирование), опционально `steps`, `model`, `hidden`, `color`.

Запись в конфиге (отступы как у соседних агентов, JSON должен остаться валидным):

```json
"<name>": {
  "mode": "primary",
  "description": "<то же, что в front-matter>",
  "prompt": "You are <name>. Use .kilo/agent/<name>.md for full context.",
  "permission": {
    "read": "allow",
    "bash": "allow",
    "edit": { "\\.(ps1|md|json|log|txt)$": "allow", "*": "ask" },
    "mcp": "allow"
  }
}
```

`permission` — это и есть границы роли: `bash: allow` для роли, которая обязана запускать процессы;
точечные расширения на `edit` и `"*": "ask"` для всего остального. Вставлять запись текстом сразу
после `"agent": {` (не пересобирать файл `json.dump`-ом — получите diff на весь конфиг).

## Тело роли

Писать так, чтобы файл был исполним целиком, без доуточнений. Обязательные разделы:

1. Роль и **границы** — что роль НЕ делает (частая ошибка: роль-оркестратор начинает сама писать код).
2. Инвентарь — пути к внешним инструментам, версии, что каждый умеет.
3. Фазы работы — что делается один раз (разведка, смоук-тесты) и что повторяется.
4. **Таблица скилов с полными абсолютными путями** к `<...>\SKILL.md` и колонкой «когда грузить»:
   так роль не зависит от того, догадается ли агент поискать скил.
5. Артефакты — куда именно писать (полные пути), куда логи, где журнал доказательств.
6. Гейты — пронумерованные проверки с командой и ожидаемым результатом.
7. Шпаргалка команд и ловушки окружения (Windows-специфика: `.cmd`/`.bat`, спавн из Node, окончания строк).
8. «Что требует владельца» — авторизации, `PATH`, деньги, решения.

## Проверка после создания (без неё роль не считать готовой)

```python
import json, os, re, yaml
t = open(role_md, encoding="utf-8").read()
yaml.safe_load(re.match(r"---\n(.*?)\n---", t, re.S).group(1))     # front-matter парсится
json.load(open(kilo_json, encoding="utf-8"))["agent"][name]         # запись на месте, JSON валиден
paths = re.findall(r"`([A-Z]:\\?[^`]+?SKILL\.md)`", t)              # пути скилов берутся из тела роли
missing = [p for p in paths if not os.path.exists(p.replace("\\\\", "\\"))]
```

`missing` должен быть пуст — кроме путей тех артефактов, которые роль обязана создать в ходе работы
(отчёт, скрипт-драйвер): их существование проверяет гейт, а не эта проверка.

## Питфоллы

- **`AGENTS.md` — защищённый файл:** правка строки требует подтверждения пользователя. Добавлять одну
  строку в таблицу, а не переписывать раздел.
- **Окончания строк.** `AGENTS.md` в таких репозиториях часто CRLF, а `kilo.json` — LF. После вставки
  строк скриптом сверять `raw.count(b"\r\n")` против одиночных `b"\n"` и не переписывать файл
  целиком в одном окончании: иначе весь файл уезжает в diff.
- **Обратные слэши в JSON-тексте промпта удваиваются**, поэтому Windows-пути в `prompt` писать как
  `C:\\Users\\...` — в JSON-строке это даст `C:\Users\...`.
- **Роль-оркестратор и роль-исполнитель — разные роли.** Не выдавать оркестратору право писать код:
  его работа — изоляция, запуск, логи и независимая проверка.
