## UI-проверки (MCP-сервер `ui`)

Интерфейсные сценарии — диалоги Revit, окна модулей, сторонние приложения — проверяются
через **UiController** (навык `wpf-desktop-ui`), а не глазами разработчика.

Предусловие: демон запущен. Проверить:

``powershell
powershell -ExecutionPolicy Bypass -File .kilo/scripts/ui-setup.ps1 (запускай через `powershell -File`) -Check
``

Как устроено:

| Что | Чем |
|---|---|
| Начало любого UI-сценария | `ui_state` — показывает, к какому окну подключён демон |
| Найти элемент | `ui_ai_find` — по AutomationId надёжнее, чем по тексту |
| Доказать, что запись сработала | `ui_set_value` → **`ui_get_value`** (read-back обязателен) |
| Проверить таблицу | `ui_grid_read` |
| Зафиксировать состояние окна | `ui_capture` — возвращает картинку |
| Объяснить, почему не дождался | `ui_wait_element` — причина в поле `suggestions` |

Что считать доказанным для UI:

- [ ] Значение прочитано обратно и совпадает с ожидаемым
- [ ] В логе приложения есть запись о событии (не только `success: true` в ответе инструмента)
- [ ] `ui_capture` показывает ожидаемое состояние, если состояние видно глазом
- [ ] Указано, какое окно проверялось и в каком состоянии (развёрнуто/свёрнуто)

Типовые ловушки (из практики, не из документации):

- Ячейка или поле может быть **read-only**: запись отчитывается об успехе, значение не меняется.
  Именно read-back это ловит.
- `NavigationView` отдаёт пункты как `DataItem` без `Invoke`/`SelectionItem` — работает только
  клик по координатам.
- Скриншот делается с рабочего стола: если окно перекрыто, на снимке будет другое окно.
  Перед capture окно поднять.
- Демон держит **одно окно за раз**: для второго приложения нужен `target`/`--active`.
